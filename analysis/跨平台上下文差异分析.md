# OpenClaw 在 macOS 和 Windows 上的 LLM 上下文差异分析

## 1. 核心运行时信息差异

### 1.1 操作系统标识 (`attempt.ts:2015`)

```typescript
os: `${os.type()} ${os.release()}`;
```

| 平台    | `os.type()`  | `os.release()` | 最终值示例              |
| ------- | ------------ | -------------- | ----------------------- |
| macOS   | `Darwin`     | `23.5.0`       | `Darwin 23.5.0`         |
| Windows | `Windows_NT` | `10.0.22631`   | `Windows_NT 10.0.22631` |

### 1.2 系统架构 (`attempt.ts:2016`)

```typescript
arch: os.arch();
```

| 平台                  | 常见值  |
| --------------------- | ------- |
| macOS (Intel)         | `x64`   |
| macOS (Apple Silicon) | `arm64` |
| Windows               | `x64`   |

## 2. Shell 检测与配置（最关键的差异）

### 2.1 Shell 名称检测 (`shell-utils.ts:101-145`)

**Windows 逻辑**：

```typescript
if (process.platform === "win32") {
  if (process.env.POWERSHELL_DISTRIBUTION_CHANNEL) {
    return "pwsh"; // PowerShell 7+
  }
  return "powershell"; // PowerShell 5.1
}
```

**macOS/Linux 逻辑**：

```typescript
const envShell = process.env.SHELL?.trim();
// 根据环境变量判断：BASH_VERSION, ZSH_VERSION, FISH_VERSION 等
if (process.env.BASH_VERSION) return "bash";
if (process.env.ZSH_VERSION) return "zsh";
if (process.env.FISH_VERSION) return "fish";
```

### 2.2 Shell 执行配置 (`shell-utils.ts:42-70`)

**Windows**：

```typescript
return {
  shell: resolvePowerShellPath(), // 优先 PowerShell 7
  args: ["-NoProfile", "-NonInteractive", "-Command"],
};
```

**macOS/Linux**：

```typescript
const shell = envShell && envShell.length > 0 ? envShell : "sh";
return { shell, args: ["-c"] };
```

> **设计原因**：Windows 的 `cmd.exe` 无法正确捕获 `ipconfig`、`systeminfo` 等系统工具的输出（它们使用 `WriteConsole` API 直接写入控制台），而 PowerShell 能正确重定向输出到 stdout。

## 3. Runtime 行构建（传递给 LLM 的关键信息）

`system-prompt.ts:691-728` 构建的 Runtime 行格式：

```
Runtime: agent=xxx | host=xxx | os=Darwin 23.5.0 (arm64) | node=v20.11.0 | model=openai/gpt-4 | shell=zsh | channel=web | capabilities=none | thinking=off
```

**LLM 可见的平台标识**：

- `os=Darwin 23.5.0 (arm64)` vs `os=Windows_NT 10.0.22631 (x64)`
- `shell=zsh` vs `shell=pwsh`

## 4. 工具执行层的平台适配

### 4.1 路径处理 (`bash-tools.exec.ts`)

- **Windows**：路径分隔符为 `\`，盘符前缀如 `C:\`
- **macOS**：路径分隔符为 `/`，根目录为 `/`

### 4.2 进程终止 (`shell-utils.ts:170-191`)

**Windows**：

```typescript
spawn("taskkill", ["/F", "/T", "/PID", String(pid)], {
  stdio: "ignore",
  detached: true,
});
```

**macOS/Linux**：

```typescript
process.kill(-pid, "SIGKILL");
```

## 5. 引导 LLM 生成平台适配脚本的机制

### 5.1 直接标识注入

LLM 通过 Runtime 行中的 `os` 和 `shell` 字段**直接知道当前平台**，从而：

- Windows：生成 PowerShell 脚本（`.ps1`）
- macOS：生成 Bash/Zsh 脚本（`.sh`）

### 5.2 工具描述中的平台提示

`system-prompt.ts:248` 中对 `exec` 工具的描述：

```
exec: "Run shell commands (pty available for TTY-required CLIs)"
```

### 5.3 工作区路径引导

`system-prompt.ts:510-513`：

```typescript
"## Workspace",
`Your working directory is: ${displayWorkspaceDir}`,
workspaceGuidance,
```

路径格式本身就是平台暗示（`/Users/xxx` vs `C:\Users\xxx`）。

### 5.4 沙箱环境的额外提示

`system-prompt.ts:516-562` 中，如果启用沙箱：

```
"## Sandbox",
"You are running in a sandboxed runtime (tools execute in Docker).",
"Sandbox container workdir: /workspace",
```

## 7. 总结

OpenClaw 通过以下策略确保 LLM 生成平台适配的脚本：

| 策略             | 实现方式                   | 效果                              |
| ---------------- | -------------------------- | --------------------------------- |
| **操作系统标识** | `os.type() + os.release()` | LLM 知道是 Darwin 还是 Windows_NT |
| **Shell 类型**   | `detectRuntimeShell()`     | LLM 知道用 pwsh 还是 bash/zsh     |
| **系统架构**     | `os.arch()`                | LLM 知道是 x64 还是 arm64         |
| **工作区路径**   | `displayWorkspaceDir`      | 路径格式暗示平台                  |
| **工具配置**     | `getShellConfig()`         | 底层自动选择正确的 shell 执行命令 |

**核心设计思想**：将平台信息**显式注入系统提示**，让 LLM 在生成脚本时能够根据 `os` 和 `shell` 字段选择合适的命令语法和脚本格式，同时底层执行引擎通过 `getShellConfig()` 确保命令在正确的 shell 环境中执行。
