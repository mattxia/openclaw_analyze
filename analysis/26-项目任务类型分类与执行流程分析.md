# OpenClaw 项目任务类型分类与执行流程分析

## 一、概述

OpenClaw 是一个多通道 AI Agent 平台。项目支持 **8 种核心任务执行类型**，通过 **4 条执行通道（Lane）** 实现资源隔离与并发控制，底层统一由 **Pi-Agent SDK** (`@mariozechner/pi-agent-core`) 驱动 LLM 推理循环。

## 二、任务分类总览

| 序号 | 任务类型 | 触发方式 | 执行通道 | 生命周期 | 典型场景 |
|------|----------|----------|----------|----------|----------|
| 1 | **一次性Agent调用** | CLI/Gateway RPC | `main` | 单次运行→结束 | 用户直接提问 |
| 2 | **自动回复运行** | 消息通道接入 | `main` | 单次运行→结束 | 收到WhatsApp消息 |
| 3 | **心跳运行** | 定时器周期触发 | `main` | 单次运行→结束 | 每30分钟检查 |
| 4 | **Cron主会话任务** | 定时调度+systemEvent | `main` | 定时触发→结束 | 定时提醒 |
| 5 | **Cron隔离Agent任务** | 定时调度+agentTurn | `cron` / `nested` | 独立会话→结束 | 每日报告生成 |
| 6 | **子Agent运行** | sessions_spawn工具 | `subagent` | 独立会话→公告结果 | 并行代码审查 |
| 7 | **长时Shell进程** | exec工具后台模式 | `main`（进程层） | 启动→后台运行→结束 | 长时间编译 |
| 8 | **嵌套Agent运行** | Cron/子Agent内部的子调用 | `nested` | 嵌套→结束 | Cron中调用子Agent |

  Main = "main",         // 主通道：入站消息、心跳、CRON主会话

  Subagent = "subagent", // 子Agent通道：sessions_spawn派生的子Agent

总控在 [src/process/command-queue.ts](file:///d:/prj/openclaw_analyze/src/process/command-queue.ts#L37-L69):

```typescript
// 全局队列状态（基于 globalThis 的符号键保证打包后单例）
const queueState = resolveGlobalSingleton(COMMAND_QUEUE_STATE_KEY, () => ({
  gatewayDraining: false,
  lanes: new Map<string, LaneState>(),
  nextTaskId: 1,
}));
```

每个 lane 的调度通过 `enqueueCommandInLane()` 进行：
- 按 **session lane** (`session:<key>`) 排队保证同一 session 只有一个活跃 run
- 按 **global lane** (`main`/`cron`/`subagent`) 限制全局并发数
- `maxConcurrent` 默认值：`main`=4, `subagent`=8, 其余=1

### 4.8 嵌套Agent运行 (Nested Agent Run)

**入口**：Cron 任务内部通过 `sessions_spawn` 创建子 Agent

**特点**：
- 执行通道：`nested`（防止 Cron lane 死锁）
- 子Agent在 `subagent` lane 上运行
- 保持在 `nested` lane 上等待完成

```typescript
// src/agents/pi-embedded-runner/lanes.ts
export function resolveGlobalLane(lane?: string) {
  const cleaned = lane?.trim();
  // Cron 任务持有 cron lane；内部操作必须用 nested 避免死锁
  if (cleaned === CommandLane.Cron) {
    return CommandLane.Nested;
  }
  return cleaned ? cleaned : CommandLane.Main;
}
```
